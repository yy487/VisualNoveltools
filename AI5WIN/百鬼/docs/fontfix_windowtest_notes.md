Runtime result:

```text

but it is still screen-sized (2554x1437 captured on a 2560x1440 desktop) and
```

Current conclusion:

```text
The game no longer needs the popup/topmost style to reproduce the black-screen
state. The remaining blockers are fullscreen-sized window dimensions and the
fullscreen-oriented DirectDraw flipping surfaces. A real windowed patch needs:

1. Window size patch around sub_429710/sub_429F30.
2. Primary surface flags in sub_43F690 changed away from FLIP|COMPLEX.
3. A windowed blit path or clipper/backbuffer path replacing the attached
   fullscreen backbuffer assumption.
```

Additional experimental patches now covered by
`H:\IDA-PRO-MCP\tools\patch_baigui_windowtest.py`:

```text
0x0042972C -> 0x004297A0 stub:
            Replace the desktop-sized GetSystemMetrics window parameters with
            fixed 640x480 creation parameters before CreateWindowExA receives
            the v3 parameter block.

0x00407ED9 / 0x00407F10 / 0x00407F42 / 0x00407F7E / 0x00407FBE / 0x00408007:
            Route the key sub_407C70 startup calls through tiny trace stubs at
            0x004080A0.  Each stub writes a stage marker to 0x004A7010, then
            tail-jumps to the original target without changing the argument
            stack.

0x0040807F:
            Route the final WINNLSEnableIME call through another trace stub.
            Stage 0xA346 means startup reached the success path after document
            initialization.

0x000A8254: AI5FIX.ini -> AI5WND.ini
            Windowtest uses a separate ini. AI5WND.ini currently sets
            LockSurface=0 so the dword_765CFC offscreen path is created.
            It now points ArcMesName to mes_chs_rebuilt.arc and ArcDataName to
            data_fontfix.arc.

0x0003F060 -> 0x0043FA40 stub:
            Save the HWND passed to DirectDraw init at 0x004A7004.

0x0003F78D -> 0x0043F9A0 stub:
            Create a DirectDraw clipper, SetHWnd(saved HWND), attach it to the
            primary surface, release the temporary clipper pointer, then skip
            attached fullscreen backbuffer initialization.

0x0042B77C / 0x0042B7D0 / 0x0044044C / 0x004404D6:
            Route the known 42B700/4402D0 BltFast refresh call sites through
            Blt wrappers at 0x00441D60 and 0x00441DE0. These wrappers build a
            client-to-screen destination RECT and call IDirectDrawSurface7::Blt
            with DDBLT_WAIT. Last Blt HRESULT is recorded at 0x004A7008 and
            wrapper call count at 0x004A700C.
```

Latest real-machine observations:

```text
Stable ai5win_fontfix.exe baseline:
- launches from E:\GAL\gui under WIN7RTM + 16BITCOLOR
- captures as a 640x480 DirectDraw surface
- shows a visible warning dialog about Mouth.Arc before gameplay
- no DATA.MR crash before that point

Windowtest:
- creates a visible overlapped window with title bar
- remains screen-sized on the test desktop (2554x1437 capture)
- client area remains black
- no visible dialog or accessibility tree

LockSurface=0 process memory:
- 0x004A7004 saved HWND: nonzero
- dword_765CC4 primary surface: nonzero
- dword_765CFC offscreen surface: nonzero
- dword_765D18 LockSurface flag: 1
- 0x004A7008 last Blt HRESULT: 0
- 0x004A700C wrapper call count: 0
```

Current conclusion:

```text
The current black screen happens before the known 42B700/4402D0 BltFast refresh
sites are hit. The next useful target is startup/control flow after DirectDraw
init rather than another Blt variant:

- trace sub_407C70 after sub_4020E0(640,480,0,0)
- check sub_4014A6(16,16), mouse/document construction, and the first calls into
  sub_43FCC0 / sub_40304E
- patch sub_429710/sub_429F30 window dimensions after rendering begins
```
