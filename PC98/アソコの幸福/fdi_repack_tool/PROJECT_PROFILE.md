# 项目档案：アソコの幸福（PC-98）FDI 重封盘

## 范围与所有权

- 项目：`アソコの幸福`，PC-98 软盘版。
- 样本角色：4 张 FDI；文档不记录本机实际路径。
- 实现语言：Rust。
- 工具边界：读取原始 FDI 文件或目录、递归发现 `fdi_unpack` v1 工作区清单和完整修改成员树，输出一张或多张新 FDI。
- 原盘保持只读；工具永远拒绝输出与源 FDI、工作区清单或成员树重叠。

## 已确认结构

- 证据等级：`confirmed-structure`。
- FDI：小端头；样本数据偏移 `0x1000`、数据大小 `0x134000`。
- 几何：1024 字节/扇区、8 扇区/轨、2 磁头、77 柱面、1232 扇区。
- 文件系统：FAT12；每簇 1 扇区、1 个保留扇区、2 份 FAT、每份 2 扇区、根目录 192 项。
- 目录项：标准 32 字节 FAT 短目录项；清单记录原始 11 字节名称、属性、时间、起始簇、大小、簇链和绝对目录项偏移。
- FDI 外层及 FAT12 层没有压缩或加密。
- FDI 头 `0x00` 字段语义仍未确认，按 `opaque-preserved` 原样保留。
- 已删除目录项、未分配区、簇尾未使用字节及其他未知数据均按 `opaque-preserved` 保留。

## 重封策略

- 源盘由清单中的 SHA-256 唯一识别，不依赖源文件名。
- 递归模式按 `_format` 内容识别工作区清单；清单可使用任意文件名并位于解包根目录任意层级。
- 成员树由“清单所在目录 + `role_paths.unpacked_root` + `archives[].output_dir`”定位，不依赖工作目录 basename。
- 批量输出由“清单相对解包根的位置 + `archives[].source_file`”映射；`source_file` 不参与原盘查找。
- 原盘文件模式只封装唯一匹配记录；原盘目录模式要求全部递归工作区记录均有唯一原盘。
- 每个清单成员还会从源盘记录的原始簇链重读并重算 SHA-256，清单内容错误时拒绝封盘。
- 清单记录的目录项必须属于对应父目录区域，并完整覆盖源盘全部活动文件和目录项。
- 成员路径集合必须与清单完全一致；当前不支持新增、删除或重命名路径。
- 未修改文件保留原簇链和数据。
- 修改文件优先保留原簇链前缀；缩短释放尾簇，增长从 FAT 空闲簇和本次释放簇中分配。
- 所有链规划完成后，先统一释放旧链，再统一写入新链，避免跨文件复用顺序影响。
- 全部 FAT 副本同步；修改成员目录项仅更新起始簇和 `u32` 大小。
- 最末簇正文后的旧字节不主动清零，以保留未知内容；文件大小限制读取边界。
- 无修改输入直接输出已校验的源字节，要求 byte-exact。
- 批量提交采用两阶段事务：全部临时文件写入并同步后才开始替换；覆盖目标先改名为独立备份，任一后续提交失败时按逆序恢复旧目标并删除新目标、临时文件和备份。

## 脚本与本地化边界

- FDI 工具不解析成员内部脚本、正文、控制符或编码。
- 本项目 AREA 文本由独立工具处理；用户已确认无 `name` 字段、引号闭合合并及游戏运行时自动换行规则。
- AREA 变长结果作为普通 FAT12 成员交给本工具，不在封盘层重复解释。

## 验证与限制

- 20 项 Rust 单元测试覆盖无修改 byte-exact、变长分配、变短释放、簇尾保留、跨文件释放簇复用顺序、空间不足、额外成员拒绝、源/成员哈希不符拒绝、目录项完整性、输入输出重叠、嵌套清单、角色目录改名、稳定输出映射、多盘批量、批量预检、提交故障回滚、覆盖策略和 CLI 模式合同。
- 一份真实四盘工作区通过递归目录入口一次处理 103、118、79、125 个成员；四张无修改输出 FDI 均与各自原盘 byte-exact。
- 四张输出再次解包后，完整 425 个盘内成员和工作区清单与封盘前解包根逐路径 SHA-256 差异为 0。
- 在 `INTER1.EXE`、`INTER2.EXE`、`GRAPH/BUNSYO.DAT` 各修改一项后，批量封盘准确报告 3 个修改成员；反向解包的 425 个成员与修改输入逐路径 SHA-256 差异为 0。
- 真实 `AREA0.DAT` 由 26,528 增长至 26,558 字节后完成封盘与反向解包；125 个成员中只有该文件变化，反解包内容 SHA-256 与输入完全一致。
- 运行游戏后被写回且 SHA-256 不再匹配清单的盘必须重新解包生成新清单，不能绕过源哈希校验。
